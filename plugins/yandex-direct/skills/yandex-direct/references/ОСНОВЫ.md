# Директ через API: что нужно знать до первого запроса

Справочник для агента. Всё, что здесь, проверено на живых кабинетах, дата проверки указана рядом с числами.

## Как устроен доступ

Токен Яндекса выпускается всегда под конкретное приложение (`client_id`). «Получить ключ» и «зарегистрировать приложение» это один процесс, отдельного ключа без приложения не существует.

Метрике и Аудиториям годится любое приложение. Директ дополнительно требует **одобренной заявки на доступ к API** под этот `client_id`. Заявка подаётся в кабинете Директа, «Мои заявки» в настройках API. Условие Яндекса: в кабинете должна быть хотя бы одна созданная кампания, запускать показы не обязательно. Срок от часа до трёх рабочих дней.

Чей это токен, выясняется одним запросом:

```sh
curl -s -H "Authorization: OAuth $TOKEN" 'https://login.yandex.ru/info?format=json'
```

Ответ отдаёт `login` и `client_id`. Если `client_id` не тот, под которым одобрена заявка, Директ ответит ошибкой 58, каким бы свежим токен ни был.

## Вызов API

```
POST https://api.direct.yandex.com/json/v5/<ресурс>
Authorization: Bearer <token>
Accept-Language: ru
Content-Type: application/json; charset=utf-8
```

Заголовок именно `Bearer`. С `OAuth`, как в остальных API Яндекса, Директ не работает.

## Обычный кабинет и агентский

`POST /json/v5/clients` с `{"method":"get","params":{"FieldNames":["ClientId","Login","Type"]}}` возвращает `Type`:

- `CLIENT` это обычный рекламодатель. Заголовок `Client-Login` не нужен и не отправляется.
- `AGENCY` это агентство. Тогда **каждый** запрос про кампании обязан нести `Client-Login: <логин клиента>`, иначе ответ `error_code 8000` с текстом про необходимость логина. Логин агентства вместо логина клиента не подходит. Список клиентов агентства даёт `/agencyclients`.

Проверено 15.09.2026: кабинет `a-tomachinsky` это `CLIENT`, кабинет `skb-kontur-ru` это `AGENCY` с 95 живыми клиентами.

## Коды ошибок, которые встречаются первыми

| Код | Что значит | Что делать |
|---|---|---|
| 53, 54 | токен невалиден или просрочен | перевыпустить токен под тем же приложением |
| 58 | под этот `client_id` заявка на API не одобрена | подать заявку в кабинете Директа либо взять токен приложения, у которого она одобрена |
| 8000 | запрос не разобран: битый формат или отсутствует `Client-Login` под агентским токеном | прочитать текст ошибки, он называет причину прямо |
| 8800 | объект не найден | чужой или удалённый идентификатор, либо несуществующий логин в `Client-Login` |

## Баллы

Каждый запрос списывает баллы кабинета, и запас конечный. Замеры 15.09.2026: на клиентском кабинете запас 120 000, проверка доступа стоила 60 баллов, чтение 8 кампаний 78 баллов. На агентском кабинете запас 3 310 000, чтение 126 кампаний 333 балла.

Отсюда практика: полные выгрузки планируются, а не дёргаются наугад, и результат кладётся в кэш. Под агентским токеном баллы по умолчанию списываются у клиента, чьи данные читаются.

## Название типа кампании расходится с интерфейсом

API отдаёт `TEXT_CAMPAIGN`, в интерфейсе после перехода на комбинаторные объявления та же кампания называется ЕПК. Человеку показываем то, что он видит в кабинете, исходное значение из API при этом не теряем.
